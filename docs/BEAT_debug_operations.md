# BEAT デバッグ大会 システム運用進行表・チェックリスト

> 対象：Minecraft内でBEATプラグインを操作する運営担当者  
> 用途：告知後に実施する短縮版デバッグ大会で、システム進行・判定・結果処理・異常系を確認するための手順書

# 1. デバッグ大会 進行表

## DBG-00｜開始前

### 運営だけで準備

- [ ] サーバー・ワールドが**本番環境のコピー**である
- [ ] `/plugins`
  - BEAT：有効
  - ProtocolLib：有効
- [ ] `/beat competition status`
  - 前回の競技が残っていない
- [ ] `/beat players`
  - デバッグ参加者が全員登録されている
- [ ] 必要なら `/beat player info <MCID>` で個別確認
- [ ] `/beat setup validate all`
  - 3競技すべて `ERROR` なし
- [ ] `/beat settings preset test`
- [ ] `/beat settings show`
- [ ] **TAのデバッグ用足切り人数を確認**
  - 少人数でも実際に足切りが発生する値にする
- [ ] `/beat whitelist all`
- [ ] `/beat whitelist status`
  - `完全同期: YES`
- [ ] `/beat debug enable`

セットアップ後はValidationだけでなく、実際にコースを走って判定位置を確認する。

### 前回のデータが残っている場合のみ

```text
/beat event reset
/beat event reset confirm
```

**「念のため」で毎回resetしない。**  
状態が分からない場合は先に `/beat competition status` を確認する。

## DBG-01｜参加者集合

- [ ] デバッグ参加者がログインできる
- [ ] `/beat players` と実際の参加者が一致
- [ ] 観戦・運営アカウントが参加者扱いになっていない
- [ ] 全員がロビーにいる
- [ ] プレイヤー表示切替などロビー機能に問題なし
- [ ] 参加者・運営を含む全プレイヤー間で押し合いが発生しない

確認：

```text
/beat competition status
```

---

## DBG-02｜高難易度

### 開始

```text
/beat competition high start
```

### 練習中に確認

- [ ] 全参加者が練習状態になった
- [ ] 5コースへ移動できる
- [ ] 飛行切替が使える
- [ ] 個人CPが使える
- [ ] 盾がホットバーの左から3番目に配られる
- [ ] 盾を構えると移動速度が下がり、細かい位置調整ができる
- [ ] Spot・Goalを踏んでも**本番記録に残らない**
- [ ] 表示・BossBarがおかしくない

時間を短縮する場合：

```text
/beat debug high-practice skip
```

### 準備時間

- [ ] 練習終了後、全員Prepare地点へ移動
- [ ] 練習時の記録が消えている
- [ ] 準備終了後、自動で本番開始
- [ ] 練習終了時に盾が回収される

### 本番中

最低限、参加者に以下を試してもらう。

- [ ] Spot取得 → +50pt
- [ ] 同じSpotを再取得 → **加点されない**
- [ ] Goal → +100pt
- [ ] 同じコースのGoal再取得 → **加点されない**
- [ ] 落下 → 現在コースのStartへ復帰
- [ ] 次コースへの進行
- [ ] 前コースへ戻る
- [ ] 現在順位・ポイント表示
- [ ] 本番開始時に盾がホットバーの左から3番目に配られる
- [ ] 再接続後も盾が重複せず再配布される

脱落判定を確認：

```text
/beat debug time next
```

実行するたびに確認：

- [ ] 脱落10秒前付近へ移動した
- [ ] 時刻到達で正しい人だけ脱落
- [ ] 条件達成済みの人は残る
- [ ] 脱落者は観戦状態になる
- [ ] 脱落者から盾が回収される
- [ ] 脱落者がコースへ戻れない
- [ ] 脱落前のポイントが残る

最後も `debug time next` で終了直前へ進める。

### 終了

- [ ] 全員が正しい終了状態になった
- [ ] End地点への移動が正常
- [ ] 完走者と競技終了者から盾が回収される
- [ ] `/beat competition status` が正常

## DBG-03｜高難易度結果

管理GUI：

**BEAT → 結果 → 高難易度**

- [ ] 順位がポイント順になっている
- [ ] 同ポイント時の順位に問題なし
- [ ] 各参加者のポイントが正しい
- [ ] 結果が確定されている

確認用：

```text

```

その後、GUIから：

- [ ] 「結果を発表」
- [ ] 確認画面で「発表する」
- [ ] 全員のチャットへ結果表示

編集した場合だけ再計算・再確定する。

## DBG-04｜タイムアタック

高難易度結果発表後に開始。

```text
/beat competition ta start
```

### 基本動作

- [ ] 開始時に参加者が固定される
- [ ] Startで計測開始
- [ ] Split 1が反応
- [ ] Split 2が反応
- [ ] Goalが反応
- [ ] タイムが記録される
- [ ] PBが更新される
- [ ] 通常記録時とPB時の表示・音が正常
- [ ] リスタートで試走破棄
- [ ] 再挑戦できる
- [ ] 順位表示が更新される
- [ ] 足切りボーダー表示が正常

### 意図的に作る参加者

- [ ] 速い記録を持つ人
- [ ] 遅い記録を持つ人
- [ ] **一度もGoalしない人**

足切り確認：

```text
/beat debug time next
```

- [ ] 20分相当の足切り
- [ ] 設定した人数だけ残る
- [ ] 記録なし参加者が正しく処理される
- [ ] 脱落者のPBが消えていない

もう一度：

```text
/beat debug time next
```

- [ ] 25分相当の足切り
- [ ] 正しい人数まで減る

最後まで進めて確認：

- [ ] 終了時に走行中の試走が終了
- [ ] End地点へ移動

## DBG-06｜耐久

```text
/beat competition endurance start
```

参加者を何人か役割分担して確認。

- [ ] Progress取得
- [ ] Progress番号が白い `P001` 形式で表示
- [ ] 次Progressが黄色の小型羊毛で表示
- [ ] 取得済みProgressが黄緑色で表示
- [ ] 将来のProgressが空色で表示
- [ ] 同じ地点の色が参加者ごとの進行状況に応じて変化
- [ ] `admins.json` 登録者には全Progressが空色固定で表示
- [ ] Admin兼参加者には運営色ではなく参加者本人のProgress色が表示
- [ ] 競技途中に接続したAdminにも全Progressが表示
- [ ] 表示に当たり判定がない
- [ ] 同じProgressの複数地点はいずれか1地点で取得
- [ ] Progressを飛ばした場合の挙動
- [ ] Chunkを離れて戻った後も表示が復帰
- [ ] 落下時の復帰
- [ ] Zone 2到達
- [ ] Zone 2到達が順位変動なしでも全体Chatに1回だけ表示
- [ ] Zone 2到達後の復帰地点変更
- [ ] Zone 3到達
- [ ] Zone 3到達が順位変動なしでも全体Chatに1回だけ表示
- [ ] Zone 3到達後の復帰地点変更
- [ ] 最高到達地点が後退しない
- [ ] Goal処理
- [ ] 完走者が待機場所へ移動

時間送り：

```text
/beat debug time next
```

### 20分判定

- [ ] Zone 2未到達者だけ脱落
- [ ] Zone 2到達済みは残る

### 25分判定

- [ ] Zone 3未到達者だけ脱落
- [ ] Zone 3到達済みは残る

### 終了

- [ ] 最高Progressが保存
- [ ] 完走者が未完走者より上位
- [ ] 脱落者の最高到達記録が残る

## DBG-09｜意図的な異常系テスト

### 再接続

競技中に1人ログアウト。

- [ ] 競技時計が止まらない
- [ ] 再接続できる
- [ ] 復帰状態がおかしくない
- [ ] 記録がおかしくならない

### 緊急回収

```text
/beat emergency collect
/beat emergency collect confirm
```

- [ ] 全員Endへ回収
- [ ] 状態が壊れていない

### 再試合

```text
/beat emergency restart
/beat emergency restart confirm
```

- [ ] 再試合待ち状態になる
- [ ] 前回記録が正しく破棄される
- [ ] 同競技を再度開始できる
- [ ] 脱落済み参加者も戻る

緊急操作は二段階確認。  
分からない問題では、いきなり `restart` や `event reset` をせず、まず状態を確認する。
